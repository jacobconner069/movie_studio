# Model Card: Movie Studio

## Models

| | Rating model | Recommender |
|---|---|---|
| Type | 3× `HistGradientBoostingRegressor` (mean, q10, q90) | Item-item collaborative filtering |
| Input | year, # ratings, genres | One or more liked movieIds |
| Output | Predicted average rating + 80% interval | Ranked similar movies |
| Training data | MovieLens latest-small, movies with ≥ 10 ratings | Same ratings, user-centered |

## Intended use

Educational/portfolio demonstration of uncertainty-aware regression and collaborative filtering. **Not** intended for real greenlighting, pricing, or content-acquisition decisions.

## Evaluation

See [`docs/RESULTS.md`](docs/RESULTS.md) (generated by `python evaluate.py --write-docs`) and the *About the model* tab. Reported: R², RMSE, MAE versus baselines; empirical 80% interval coverage; recommender hit rate @ 10 and catalog coverage versus a popularity baseline.

## Known limitations and risks

- **Population bias:** MovieLens raters are self-selected volunteers; outputs don't generalize to all audiences.
- **Popularity bias:** movies with < 10 ratings (rating model) or < 20 (recommender) are excluded, so well-known films are favored.
- **Association, not causation:** `n_ratings` correlates with rating; raising audience size would not by itself raise quality.
- **Group-level target:** predictions are for a movie's *average* rating, not any individual's.
- **Cold start:** the recommender cannot suggest brand-new movies or serve users with no liked movies.
- **Snapshot data:** the dataset reflects a past period; tastes and catalog drift.

## Maintenance

Retrain with `python train.py`; re-evaluate with `python evaluate.py`. Tests (`pytest`) run on synthetic data and don't validate real-data model quality.
